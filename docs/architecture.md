# 枝序实现说明（0.2.0）

## 进程与职责

React 管理视图和当前编辑草稿，通过 Tauri IPC 调用 Rust。Rust 使用单个互斥锁串行化数据操作；数据库、备份和附件工作在 `spawn_blocking` 上执行，不在窗口消息线程中解压文件。不启动 HTTP 数据服务。

SQLite 由 Rust 内嵌，无需外部数据库。每次操作打开连接，启用外键和 FULL 同步；数据修改使用事务。连接在恢复目录切换前关闭。单实例插件避免多个软件进程竞争同一份个人数据。

## IPC 接口

| 命令 | 输入 | 输出 |
| --- | --- | --- |
| `bootstrap` | 无 | 全部应用状态和备份状态 |
| `save_note` | `NoteInput`：ID、标题、Markdown、文件夹、标签、收藏、修订号 | 状态及新解锁的成就 ID |
| `mutate` | 带 `kind` 的操作联合类型 | 修改后的状态 |
| `import_image` | 笔记 ID、Base64 图像 | 相对附件路径 |
| `import_image_file` | 笔记 ID、用户选择的文件路径 | 相对附件路径 |
| `export_backup` | `.zhixu` 输出路径 | 更新后的状态 |
| `restore_backup` | 用户选择的备份路径 | 完整恢复后的状态 |

错误以可读字符串返回，前端展示且不会清空草稿。后端重新验证修订号、长度、图片签名、成就方式和进度范围，不能只依赖表单限制。

## 数据关系

`folders → notes` 为一对多。`notes ↔ tags` 经 `note_tags` 多对多。`attachments` 记录复制到应用目录的文件；删除笔记时将关联置空，避免删除被其他笔记 Markdown 引用的图像。`counted_notes` 是不随笔记删除的唯一 ID 账本，用于累计笔记指标。`achievements` 保存定义、当前进度与唯一的当前获得日期。撤销手动完成会清除此日期，再完成时生成新日期。

## 保存链路

`NoteSession` 区分当前草稿与已提交代次。每轮保存发送一个不可变快照；保存期间继续输入的文字不会被返回的旧内容覆盖，只更新修订号。只允许一个写请求在途，后续编辑等待前次返回的新修订号。切换、元数据操作和关闭窗口都先 `flush()`；导航与结构修改期间暂时禁止编辑，避免把过时的文件夹状态写回。

保存正文、首次写成账本、自动成就进度、解锁日期和每日写作经验奖励处于同一 SQLite 事务中。失败全部回滚；后端不会通过“最后写入获胜”覆盖新版本。

## 每日经验

数据库版本 2 新增 `experience_events`，以 `(day, task)` 为主键，独立于笔记，避免删除笔记导致经验消失。签到通过 `mutate({kind:'checkIn'})` 提交；正文去除首尾空白后发生改变且非空时，在保存事务内提交写作奖励。奖励采用唯一键冲突时不插入的方式，重复点击、同日多篇笔记、重启和恢复均不重复发奖。

`Growth` 从完整流水计算总经验与等级，历史列表只返回最近 30 条，不影响总量。等级为 `totalXp / 100 + 1`，当前等级经验为 `totalXp % 100`。`Snapshot.xpEarned` 只包含该次操作新发放的经验，前端据此显示经验和升级通知，刷新或恢复不会再次庆祝旧记录。

日期来自 Rust `Local`，客户端不能传入领取日期。内部日期函数可注入以测试跨日和时钟回拨。界面每 15 秒检查日期变化，聚焦与进入任务页时同步刷新；所有经验仍由后端判定。旧数据没有可靠的每日写作历史，不追溯补发。

## 恢复与迁移

数据根目录下的 `content/` 保存数据库和附件，`backups/` 保存自动与恢复前备份。备份通过 SQLite backup API 取得一致快照，以临时文件写入并同步后再发布。

恢复先解压到内部临时目录，禁止越界路径、符号链接、重复和未登记文件，校验文件长度、SHA-256、备份/数据库版本、SQLite 完整性及图片引用。验证通过后才备份当前数据，再将当前 `content` 改名为 `restore-previous`，把临时目录移到 `content`。若中途退出导致 `content` 不存在，下次启动将旧目录恢复。保留上一份恢复前目录直到下一次恢复。

数据库 `PRAGMA user_version` 管理版本。V1 初始化与 V2 迁移在同一事务内，验证通过才提交；迁移已有数据前制作备份，版本过新则停止打开而不是降级。恢复 V1 备份时在暂存目录完成升级与校验，之后才切换数据。未来迁移应添加 `if version < N` 分支和失败回滚测试。

## 边界与安全

仅应用管理的图片路径可经 asset protocol 读取；外部图片、原始 HTML 和脚本不会渲染执行。网页链接只能由用户点击后交给默认浏览器。测试目录覆盖、额外图片 scope 和独立测试实例仅存在于 debug 构建，不影响正式数据目录或用户运行中的应用。

首版不做加密、云同步、回收站定时清理、笔记修订历史或附件垃圾回收。完整备份恢复解压上限为 2 GB、最多 100000 个归档条目；上限属于安全保护，不能作为无限容量承诺。
