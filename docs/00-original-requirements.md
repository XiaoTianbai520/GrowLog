我准备开发一个叫 **「枝序」** 的个人成长管理桌面工具。

这个项目不是用于练手，也不是为了展示复杂技术架构，而是希望真正长期给我自己和朋友使用。

所以这个项目最重要的目标是：

**简单、稳定、易用、好安装、低成本、数据安全、长期可维护。**

项目暂定定位：

> **枝序 —— 记录知识，规划时间，看见成长。**

------

# 一、产品定位

「枝序」是一个个人成长管理工具，主要整合以下几个方向：

- 笔记
- 思维导图
- 技能树
- 日程
- Todo
- 学习记录
- 经验等级
- 成就系统

这些模块不是完全独立的，而是应该能够互相关联。

例如：

```text
日程
 ↓
完成学习任务
 ↓
记录学习时间
 ↓
关联技能
 ↓
技能获得经验
 ↓
技能升级
 ↓
解锁成就
 ↓
形成长期成长记录
```

------

# 二、核心设计原则

整个项目请始终遵循以下原则。

## 1. 不依赖 AI

第一版以及可预见的核心功能都不要依赖大模型 API。

原因：

- 不希望产生 Token 费用
- 不希望软件必须联网
- 不希望用户注册第三方 AI 服务
- 能通过普通程序逻辑完成的功能不要使用 AI

例如：

自动思维导图应该通过 Markdown 标题结构解析完成，而不是通过 AI 理解笔记。

------

## 2. Local First

项目优先采用：

**本地优先架构。**

用户安装软件以后，不注册账号、不配置数据库、不连接服务器，也可以完整使用。

核心数据保存在用户电脑本地。

第一版不考虑：

- 云服务器
- 用户账号系统
- 强制登录
- 云数据库
- 多设备同步
- 微服务

即使以后加入云同步，本地使用也应该始终能够独立工作。

------

## 3. 第一阶段只考虑 Windows 桌面端

目前暂时不考虑：

- Android
- iOS
- 移动端适配
- Web 公网版本

第一阶段目标是：

```text
枝序 Setup.exe
      ↓
双击安装
      ↓
桌面快捷方式
      ↓
打开软件
      ↓
直接使用
```

普通用户不应该需要：

- 安装 Java
- 安装 Node.js
- 安装 PostgreSQL
- 配置环境变量
- 手动启动后端服务
- 执行命令行

最终必须能够打包成一个正常的 Windows 安装程序。

# 六、自动思维导图

笔记可以自动转换成思维导图，但是完全不使用 AI。

例如笔记：

```markdown
# MySQL

## 索引

### B+树

### 联合索引

## 事务

### ACID

### MVCC

## 分库分表

### ShardingSphere
```

程序根据 Markdown 标题层级解析为：

```text
MySQL
├─ 索引
│  ├─ B+树
│  └─ 联合索引
├─ 事务
│  ├─ ACID
│  └─ MVCC
└─ 分库分表
   └─ ShardingSphere
```

然后生成思维导图。

希望支持：

- 展开
- 折叠
- 缩放
- 拖动画布
- 点击节点跳转到笔记对应标题
- 笔记修改后自动更新导图

如果 React Flow 过重，可以选择更加简单的树状渲染方案。

请优先保证使用体验。

```text

```

XP 可以来源于真实行为，例如：

- 完成学习日程
- 完成学习 Todo
- 添加学习记录
- 完成技能阶段
- 获得成就

具体 XP 算法暂时不要过度设计。

需要确保：

**XP 是成长反馈，不应该成为负担。**

用户也应该允许：

- 手动修改技能等级

# 十二、成就系统

枝序需要有完整的成就系统。

成就的目的：

**给长期使用提供正反馈。**

不要为了强迫用户使用而设计成就。

成就应该来源于真实行为。

例如：

## 笔记类

- 创建第一篇笔记
- 创建 10 篇笔记
- 创建 50 篇笔记
- 创建 100 篇笔记

## 学习类

- 第一次记录学习
- 累计学习 10 小时
- 累计学习 50 小时
- 累计学习 100 小时
- 连续学习 7 天
- 连续学习 30 天

## 技能类

- 创建第一个技能
- 拥有 10 个技能
- 一个技能达到 Lv.5
- 一个技能达到 Lv.10
- 完成一个技能分支

## 日程类

- 完成第一个计划
- 连续 7 天完成当天计划
- 单月完成率达到一定比例

# 二十五、UI 视觉风格要求

「枝序」整体视觉风格希望呈现出一种：

**类似 macOS 原生软件的高级感、克制感、秩序感和精致感。**

不是简单模仿 macOS，而是参考其设计语言：

- 简洁
- 克制
- 留白充足
- 层级清晰
- 动效细腻
- 组件统一
- 信息密度舒适
- 长时间使用不疲劳
- 看起来像真正成熟的软件，而不是普通后台管理系统

------

## 1. 整体视觉方向

希望软件给人的第一感觉是：

> 安静、现代、高级、精致、可靠。

避免传统后台管理系统常见的：

- 大量粗边框
- 高饱和颜色
- 到处都是卡片
- 每个模块都有明显描边
- 过多渐变
- 大面积纯色按钮
- 花哨阴影
- 过度圆角
- 视觉元素堆积
- 典型“Admin Dashboard”风格

整体更接近：

```text
macOS 原生应用
+
现代生产力软件
+
轻量个人成长工具
```

而不是：

```text
企业后台
+
游戏 UI
+
花哨 SaaS Dashboard
```

------

## 2. 色彩要求

整体以：

- 黑
- 白
- 灰
- 低饱和中性色

作为主要视觉基础。

主色只能作为：

- 当前选中状态
- 强调信息
- 关键操作
- 技能状态
- 成就等级
- 少量数据可视化

不要让品牌色占据大量面积。

例如枝序虽然有“枝”和“成长”的概念，但不要把整个软件做成绿色。

绿色可以作为其中一种辅助颜色，但不是全局强制主题。

颜色应该偏：

- 低饱和
- 柔和
- 耐看
- 不刺眼

------

## 3. 深色模式

深色模式需要作为完整设计，而不是简单把：

```text
白色 → 黑色
黑色 → 白色
```

进行反转。

深色模式应该考虑：

- 多层级深灰背景
- 卡片与页面背景之间轻微明度差
- 文字层级
- Hover 状态
- Divider
- 输入框
- 弹窗
- 阴影
- 高亮

避免使用完全纯黑背景。

优先考虑类似：

```text
#0E0E0F
#151516
#1C1C1E
#242426
```

这类有层次的深灰体系。

具体颜色不必严格固定，由设计系统统一决定。

------

## 4. 浅色模式

浅色模式不要使用大量刺眼纯白。

可以使用：

```text
页面背景：轻微灰白
内容区域：接近白色
分割区域：极浅灰
```

制造类似 macOS 的层次感。

页面不同区域的区分应更多依赖：

- 留白
- 明度
- 间距
- 轻微阴影
- 模糊
- 层级

而不是粗边框。

------

## 5. 圆角

整体使用统一的圆角设计。

但不要：

> 每个东西都变成“大圆角卡片”。

建议：

- 小型输入框：中等圆角
- 按钮：中等圆角
- 面板：较大圆角
- Modal：较大圆角
- Tooltip：小圆角

需要建立统一的 Radius Token。

例如：

```text
小圆角
中圆角
大圆角
```

不要在不同页面随意出现多个不一致圆角值。

------

## 6. 阴影

阴影应该非常克制。

优先用于：

- 弹窗
- 浮动菜单
- Command Palette
- Dropdown
- Tooltip
- 拖拽元素

普通页面内容不要全部加明显阴影。

阴影应该：

- 很淡
- 很柔
- 范围较大
- 不出现明显黑边

营造轻微悬浮层级即可。

------

## 7. 毛玻璃效果

可以适当加入 macOS 风格的：

**Blur / Frosted Glass / 半透明效果**

例如：

- 顶栏
- 侧边栏
- 浮动工具栏
- Command Palette
- Modal
- 快捷操作面板

但是必须克制。

不要让整个软件所有区域都变成毛玻璃。

毛玻璃应该作为：

> 层级表达

而不是视觉噱头。

------

## 8. 左侧导航栏

左侧导航是整个软件的重要视觉区域。

风格希望类似成熟的 macOS 生产力软件。

例如：

```text
枝序

首页

工作区
  笔记
  思维导图
  技能树

规划
  日程
  Todo

成长
  学习记录
  成就

────────

设置
```

导航栏要求：

- 简洁
- 图标统一
- 当前页面高亮克制
- Hover 动画柔和
- 不使用大色块
- 不使用粗重描边

选中项可以使用：

```text
浅灰背景
+
稍强文字
+
小面积强调色
```

而不是整个菜单变成品牌色。

------

## 9. 图标

图标风格需要保持统一。

优先：

- 线性图标
- 细线条
- 简洁
- 几何
- 视觉重量统一

不要混用：

- 卡通图标
- Emoji
- 3D 图标
- 粗线图标
- 不同风格图标库

Emoji 可以用于：

- 成就
- 少量状态表达

但不要成为主要 UI 图标体系。

------

## 10. 字体

字体需要营造：

- 清晰
- 精致
- 现代
- 长时间阅读舒适

中文尤其要注意排版。

应该设计明确的：

```text
页面标题
模块标题
正文
辅助文字
弱化文字
数据
按钮
```

字体层级。

避免所有文字大小差异非常大。

整体 Typography 应该偏克制。

标题不需要动辄：

```text
40px
48px
64px
```

这种宣传网站式大标题。

这是桌面工具，不是 Landing Page。

------

## 11. 留白

留白非常重要。

不要试图把整个屏幕塞满。

例如一个设置页面：

错误：

```text
设置
账号设置主题设置数据设置通知设置备份设置……
```

正确：

```text
设置

外观
────────────

主题
浅色 / 深色 / 跟随系统


数据
────────────

数据目录

自动备份

导入 / 导出
```

通过：

- 间距
- 分组
- 留白

建立层级。

------

## 12. 卡片设计

尽量减少“Dashboard 卡片化”。

不要：

```text
┌──────┐ ┌──────┐ ┌──────┐
│ 卡片 │ │ 卡片 │ │ 卡片 │
└──────┘ └──────┘ └──────┘

┌──────┐ ┌──────┐ ┌──────┐
│ 卡片 │ │ 卡片 │ │ 卡片 │
└──────┘ └──────┘ └──────┘
```

所有东西都装进卡片会让软件看起来非常像模板后台。

可以更多使用：

- Section
- List
- Split View
- Sidebar
- Inspector
- Panel
- Divider

这些桌面软件布局方式。

------

## 13. 动效

动效需要达到：

**有感觉，但不会被用户注意到“这里有动画”。**

例如：

- 页面切换
- Hover
- Tab 切换
- Dropdown
- Modal
- 展开技能节点
- 展开思维导图
- 完成 Todo
- 解锁成就

都可以有非常轻微的：

```text
Fade
Scale
Slide
Spring
```

但时间要短。

避免：

- 大幅度弹跳
- 长时间动画
- 大面积转场
- 夸张粒子效果

整体应该接近 macOS 的微动效体验。

------

## 14. 技能树视觉

技能树不要做成传统企业流程图。

希望更接近：

**精致的知识网络 / 成长地图。**

节点应该：

- 简洁
- 清晰
- 有层次
- 能体现等级
- 能体现学习状态

但是避免：

- 游戏技能树巨大光效
- 金色边框
- 火焰
- 复杂粒子
- 赛博朋克
- MMORPG 风格

游戏化应该隐藏在细节里。

例如：

```text
Redis

Lv.4
██████░░░░
```

而不是做成 RPG 游戏按钮。

------

## 15. 成就页面视觉

成就系统可以比其他页面稍微有更多视觉表现。

例如：

```text
成就

12 / 48 已解锁
```

下面展示徽章。

不同稀有度允许有轻微颜色区分。

但仍然保持整体高级感。

例如：

```text
普通：灰
稀有：低饱和蓝
史诗：低饱和紫
传说：柔和金色
隐藏：深灰
```

不要使用：

- 荧光
- 强发光
- 彩虹渐变
- 游戏装备框

------

## 16. 首页 Dashboard

首页不要做成企业数据驾驶舱。

不要出现：

```text
8 个 KPI 卡片
+
6 个图表
+
3 个饼图
```

首页应该更像一个个人工作台。

例如：

```text
晚上好

8 月 31 日 · 周一

今天
────────────────

20:00  学习 Redis

22:00  整理笔记


最近
────────────────

Redis
Lv.4

Java
Lv.8


继续学习
────────────────

ShardingSphere 分片算法
```

强调：

- 今天
- 下一步
- 最近状态

而不是大量数据统计。

------

## 17. 页面布局

优先使用桌面软件常见结构：

```text
Sidebar
+
Content
+
Optional Inspector
```

例如笔记：

```text
┌─────────┬──────────────┬──────────┐
│ Sidebar │  Note Editor │ Outline  │
│         │              │          │
│ 笔记列表 │              │ 目录      │
│ 文件夹   │              │ 标签      │
└─────────┴──────────────┴──────────┘
```

技能树：

```text
┌─────────┬─────────────────────────┐
│ 分类     │                         │
│         │       Skill Tree        │
│ 技能列表 │                         │
│         │                         │
└─────────┴─────────────────────────┘
```

避免所有页面都使用完全一样的：

```text
顶部标题
+
下面六张卡片
```

------

## 18. 交互设计

需要考虑成熟桌面软件应有的交互。

例如：

- 右键菜单
- Ctrl + K 全局搜索
- Ctrl + N 新建
- Ctrl + S 保存
- Delete 删除
- Esc 关闭弹窗
- 拖拽
- 多选
- Context Menu
- Tooltip

如果某个操作可以通过：

```text
右键
```

快速完成，就不要强迫用户进入三级菜单。

------

## 19. 空状态

空页面不要只是显示：

```text
暂无数据
```

应该提供下一步动作。

例如技能树为空：

```text
还没有技能

从你正在学习的一项技能开始。

[ 创建第一个技能 ]
```

笔记为空：

```text
开始记录你的第一个知识点。

[ 新建笔记 ]
```

保持简洁，不需要大型插画。

------

## 20. 最终视觉判断标准

开发任何页面时，请问自己：

如果把 Logo 和「枝序」两个字隐藏，

这个界面看起来是否仍然像：

> 一款成熟、精致、长期维护的 macOS 生产力软件？

如果答案更像：

- 后台管理模板
- Bootstrap 页面
- 游戏 UI
- 普通网页
- AI 自动生成的 Dashboard

那么需要重新设计。

最终希望达到：

> **简洁但不简陋，克制但不单调，精致但不花哨，有一点成长与游戏化气质，同时保持桌面生产力软件应有的专业感。**

在后续设计页面时，请始终以这一套视觉规范作为统一设计语言，不要每个模块使用不同的设计风格。
